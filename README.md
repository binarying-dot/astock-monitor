# A股下跌家数监控

每个交易日自动巡盘全市场涨跌家数，当**下跌家数突破阈值**时，通过企业微信群机器人推送提醒到你手机。

## 监控规则

| 项目 | 配置 |
|---|---|
| 监控时段 | 工作日 **9:25 – 15:00**（午休 11:30–13:00 自动跳过，节假日自动跳过） |
| 检测频率 | 每 **5 分钟** 一次（约 50 次/交易日） |
| 触发阈值 | 下跌家数 **≥ 5000 家**（可调整，见下） |
| 推送节奏 | **当天首次触发推一次**，之后不再重复，次日自动重置 |
| 数据范围 | 沪深京全市场，剔除停牌/无成交 |

## 运行机制（重要）

GitHub 免费账号的 `schedule` 定时触发**极不规律**：`*/5 * * * *` 名义上每 5 分钟一次，
实测每 1–2 小时才真正触发一次，个别交易日盘中完全不触发。

因此本项目不依赖触发频率，而是：

1. **提高被触发的机会**：cron 设为 `*/5 * * * *`（全天每 5 分钟给一次机会）；
2. **一次触发就循环覆盖整个时段**：脚本被触发后，若处于 9:25–15:00 之间，
   会在**同一个 job 内自行循环检测**，每 5 分钟一次，直到 15:00 收盘才退出；
3. **`concurrency` 互斥**：保证同一时间只有一个会话在跑，不会重复推送。

> 实测：一次触发后成功在**同一个云端任务里连续运行 11.1 分钟、完成 8 次检测**后正常退出。
> 单次 job 上限 6 小时，本任务最长 5 小时 45 分钟，留有余量。

非交易时段被触发时脚本毫秒级退出，不消耗资源。

## 数据源

双源自动降级，任一路不通自动切换：

1. **东方财富** `push2.eastmoney.com`（首选，GitHub 服务器上通常可用）
2. **新浪财经** `vip.stock.finance.sina.com.cn`（备用）

## 配置

配置都在仓库的 **Actions 变量 / 密钥**中（Settings → Secrets and variables → Actions）：

| 名称 | 类型 | 说明 |
|---|---|---|
| `WECOM_WEBHOOK` | Secret | 企业微信群机器人 Webhook 地址 |
| `THRESHOLD` | Variable | 触发阈值，默认 5000。例如改成 `4500` 会更容易触发 |

**换阈值**：改 `THRESHOLD` 变量即可，不用改代码。

其他可选环境变量（一般不需要动）：

| 名称 | 默认 | 说明 |
|---|---|---|
| `INTERVAL_MIN` | 5 | 循环内检测间隔（分钟） |
| `SESSION_START` | 09:25 | 开始检测时间 |
| `SESSION_END` | 15:00 | 收盘时间 |
| `LOOP` | 1 | 设为 `0` 则只检测一次、不循环 |

## 手动测试

Actions → 左侧「A股下跌家数监控」→ **Run workflow**：

- 勾选 **跳过时段闸门与循环（测试用，只跑一次）** → 立即抓一次数据并判断（收盘后也能测）
- 不勾选 → 当时段内会启动完整循环

## 运行状态

- 每次运行结果写在 **Actions 运行日志** 和 **Summary** 里（含涨跌家数、占比、耗时）
- `state.json` 记录当天是否已推送、最后一次检测的家数，由 workflow 自动提交回仓库
- 该提交同时起到「保活」作用，避免仓库 60 天无活动导致定时任务被平台停用

## 文件说明

| 文件 | 作用 |
|---|---|
| `monitor_actions.py` | 监控主脚本（纯标准库，零依赖） |
| `.github/workflows/monitor.yml` | 调度配置（UTC cron，脚本内部使用北京时间） |
| `state.json` | 当日推送状态与最近检测值（自动生成/提交） |
| `test_loop.py` | 用模拟时钟验证时段闸门与循环逻辑（本地运行，不联网） |
